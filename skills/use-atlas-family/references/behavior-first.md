# Behavior-first construction

Separate requested shape, resizing, movement, visibility, materials and interfaces. Discover only the current capability. Known typed actions may be called directly; a workflow is guidance rather than mandatory repeated help.

## Resizing: a cabinet, enclosure or support

Create/reuse the intended types before parameter definitions. Establish reference planes with labeled dimensions. `constrained_extrusion` binds a rectangular framework and optional start/end parameters. Test two requested types using geometry flex and compare actual bounds/dimensions with the brief before adding fasteners or nested detail.

Fixed cylinder/box primitives retain their literal dimensions. A length parameter with the same name as a dimension is not an association. Curved profiles support declared native editable forms; this does not imply every arc/spline is formula-driven. Request the forms/constraints contracts and disclose unsupported outline behavior explicitly.

## Movement: a sliding panel, stem or telescoping part

A component transform is a one-time edit unless a supported family association drives it. For a translating extrusion, parameter-driven start/end extents can move both ends while keeping their difference constant where the native form supports those associations. Establish the required formulas and measure both positions and dimensions under restoring probes. This does not establish arbitrary rigid-body translation or rotations of all solids; discover and qualify that combination before using it.

Visibility hides geometry and cannot demonstrate movement. `behavior_probe` provides declared measurements; choose bounds/positions for displacement, not visibility or volume alone. For instance controls, test two independently placed instances. If you cannot demonstrate the requested mechanism, report that before finishing decorative geometry.

## Connections: any duct/pipe/electrical accessory

Use native faces and independently inspect connector position, outward direction and size. A connector-diameter association resizes the connector only; measure the physical bore separately. A loadable family with ports is distinct from a demonstrated project connection. For requested project use, create the compatible fixture and inspect actual connections. Do not invent ratings or certifications from a generic modeling brief.

## Interpret control_summary

`connector`, `visibility`, `material`, `geometry_extent`, `dimension_constraint`, `nested_type` and `element_property` describe direct native bindings. No binding can mean metadata or an indirect formula driver; formula dependencies are not proven by this summary. Use formulas and measured probes to establish actual behavior. Keep static geometry when the brief calls for one fixed size, but label it honestly.

For a small unspecified request, state reasonable modeling assumptions and intended scope rather than automatically imposing a complicated engineering program. The stricter proof steps apply to behaviors actually requested or claimed.
